      - Base AppException extends RuntimeException (clean transactional rollback semantics)

    - Never expose stacktraces, database constraints, or internal server IPs in client-facing error payloads
    - Always attach a unique Correlation ID / Trace ID to both response payload and server logs for instant production troubleshooting

    - Core Architecture & Storage Internals
      - In-Memory Single-Threaded Event Loop (I/O Multiplexing - epoll/kqueue) vs Multi-threaded I/O in Redis 6+
      - Memory Management & Maxmemory Eviction Policies (volatile-lru, allkeys-lru, volatile-lfu, allkeys-lfu, volatile-ttl, noeviction)
      - Persistence Mechanisms: RDB (Snapshots, BGSAVE, Copy-on-Write) vs AOF (Append-Only File, fsync: always/everysec/no, AOF Rewrite) & Hybrid Persistence
    - Redis Data Structures & Enterprise Use Cases
      - String (Caching, Atomic Counters via INCR/DECR, Bitmaps for Daily Check-in / Active Users, Bitfields)
      - Hash (User Sessions, Shopping Carts, Objects with selective field updates)
      - List (Message Queues via LPUSH/RPOP, Blocking Queues via BRPOP, Capped Activity Feeds)
      - Set (Unique Visitors, Tagging systems, Set Operations: SINTER, SUNION, SDIFF for Mutual Friends & Recommendations)
      - Sorted Set / ZSet (Real-time Leaderboards, Priority Queues, Sliding Window Rate Limiting using timestamp scores)
      - Geospatial / GEO (Geohash, Location Tracking, GEOADD, GEORADIUS, Nearby Search)
      - HyperLogLog (Cardinality estimation for massive Unique Pageviews with only ~12KB memory)
      - Streams (Append-only log, Consumer Groups, Pending Entries List - PEL, XADD, XREADGROUP, XACK, lightweight Kafka alternative)
      - Probabilistic Structures: Bloom Filter & Cuckoo Filter (Pre-checking key existence to eliminate Cache Penetration)
    - Spring Data Redis & Client Drivers Integration
      - Jedis vs Lettuce: Why Lettuce (Netty-based asynchronous & thread-safe) is Spring Boot default
      - RedisTemplate<K, V> & StringRedisTemplate configuration

      - Spring Cache Abstraction (@EnableCaching, @Cacheable, @CachePut, @CacheEvict, @Caching)
      - Custom RedisCacheManager (Per-cache dynamic TTL configuration, disabling null caching, custom key generators)
    - Caching Strategies, Patterns & Production Pitfalls
      - Caching Patterns: Cache-Aside (Lazy Loading), Write-Through, Write-Behind (Write-Back), Refresh-Ahead
      - The Big Three Cache Disasters (Bộ ba thảm họa Cache & Cách khắc phục triệt để):
        - Cache Penetration (Truy vấn key không tồn tại): Solution via Cache NULL with short TTL & Bloom Filter
        - Cache Breakdown / Stampede (Key HOT hết hạn đột ngột): Solution via Mutex Distributed Lock & Logical Expiration
        - Cache Avalanche (Hàng loạt key hết hạn đồng thời): Solution via Random Jitter TTL & Multi-level Caching
      - Cache - Database Consistency: Cache-Aside update order (Update Database first, then Delete Cache; Handling race condition via Transactional Outbox / CDC Debezium)
      - Two-Level Caching Architecture (L1 Local Memory with Caffeine / Ehcache + L2 Distributed Redis)
    - Distributed Locks & Concurrency Control
      - Primitive SETNX Pitfalls: Expiration before task completion, no reentrancy, premature release
      - Redisson Framework Deep Dive:
        - Watchdog mechanism (Automatic lock lease time renewal / auto-heartbeat)
        - RLock, RFairLock, RReadWriteLock, RSemaphore, RCountDownLatch
      - Redlock Algorithm: Multi-node distributed lock consensus & Martin Kleppmann's safety critique
    - Messaging & Real-Time Communication
      - Redis Pub/Sub (PUBLISH, SUBSCRIBE, PSUBSCRIBE) — Fire-and-forget, ephemeral, no persistence
      - Redis Streams vs Kafka/RabbitMQ (Persistent messages, Consumer Groups, Dead-letter handling)
    - High Availability, Clustering & Scalability
      - Redis Master-Replica Replication (Asynchronous replication, Replication Buffer, PSYNC)
      - Redis Sentinel (Quorum, Sentinel Failover, Split-Brain prevention)
      - Redis Cluster Architecture (16384 Hash Slots, CRC16 hashing, slot resharding, cross-slot multi-key operations & {hash-tag})
    - Enterprise Best Practices & Production Checklist
      - Connection Pooling configuration (Lettuce Connection Pool sizing with commons-pool2, timeout settings)
      - Strictly avoid KEYS * in production (blocks event loop); always use SCAN with MATCH & COUNT
      - Strict Key Naming Convention (namespace:entity:id:field e.g. ecommerce:order:1024:items)
      - Enforce TTL on every cache key to prevent memory leaks
      - BigKey & HotKey detection & remediation (redis-cli --bigkeys, splitting large collections, local caching for hotkeys)
      - Lua Scripting (RedisScript) for atomic operations (Rate Limiting, multi-step balance checks)
